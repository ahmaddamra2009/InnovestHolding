# Security controls (PR-A, updated by PR-B and PR-C1)

Every statement below was checked against the code on 2026-10-22. All numbers are defaults in
`Infrastructure/SecurityOptions.cs`; they can be overridden by configuration, e.g. the environment variable
`Security__Login__UserFailureLimit=5`. No appsettings entry is required.

| Control | What it does | Where |
|---|---|---|
| Antiforgery | `AutoValidateAntiforgeryTokenAttribute` is a global filter: every POST/PUT/PATCH/DELETE needs a valid token. Antiforgery cookie: HttpOnly, SameSite=Strict, Secure (always, except Development = same as request). Only exception: `HomeController.Error` (`[IgnoreAntiforgeryToken]`, because the exception handler re-executes a failed POST there). | `Program.cs` (`AddControllersWithViews`, `AddAntiforgery`); `Controllers/HomeController.cs` |
| Rate limit - public forms | `Register` and `Contact`: **5 requests / 10 min** per IP **per action**. The partition is `ip\|Controller/Action` taken from the matched endpoint, not the URL, so every URL of an action shares one bucket: `/forms/register`, `/en/forms/register` and the alias `/Home/Register` (kept one release) are one bucket; the same for `contact`. Since PR-C1 the forms live in `FormsController` (POST only, moved off the page URLs so `/contact` and `/en/contact` can be pages); the routes are pinned attribute routes, so `/Forms/Contact/1`, `/Admin/Forms/Contact`, `/contact` and `/en/contact` do not write (404 or no form action), and `GET /forms/register` is 404. Over the limit: 429 + `Retry-After`; `[JsonFormEndpoint]` marks the form actions, whose 429 body is JSON in the page's language, other endpoints get plain text. | `Infrastructure/RateLimitPolicies.cs`; `Controllers/FormsController.cs` |
| Rate limit - login | `POST /Account/Login`: **30 requests / 5 min** per IP (fixed window, no queue). | `RateLimitPolicies.cs`; `Controllers/AccountController.cs` |
| Login lockout | Failed password checks are counted per **account** (keyed on user id, so every spelling the DB collation resolves to shares one counter; unknown names are keyed on their NFKC-normalised upper-case form) and per IP: **5 per account / 20 per IP within 15 min, then locked 15 min**. A locked key skips BCrypt. A successful login clears the account counter only, not the IP counter. Settings > ChangePassword uses the same account key (a wrong current password counts). Memory guard: the unknown-name and IP stores each cap at 10 000 keys; when full, new keys are refused (fail closed). State is in memory: lost on restart/app-pool recycle, not shared across instances. | `Infrastructure/LoginThrottle.cs`, `SecurityOptions.cs`; `Controllers/AccountController.cs`; `Controllers/Admin/SettingsController.cs` |
| Request body size | Register and Contact: `[RequestSizeLimit]` of **32 KB** (`InputLimits.PublicBodyBytes`, on `FormsController`); Login POST: **8 KB** (`InputLimits.LoginBodyBytes`); every admin action: **8 MB** (`InputLimits.AdminBodyBytes` on `AdminControllerBase`; the content editor's worst case is ≈ 4.9 MB, and the page editor's fields stay far below it). Enforced by the framework when the endpoint is selected (before antiforgery reads the form); there is no custom middleware. | `Controllers/FormsController.cs`, `Controllers/AccountController.cs`, `Controllers/Admin/AdminControllerBase.cs` |
| Client IP key (PR-B) | Every per-IP control (form and login rate limits, login IP lockout) keys IPv4 on the full address and IPv6 on its **/64 prefix** (an IPv4-mapped IPv6 address counts as IPv4), so rotating the low 64 bits does not buy a new budget. | `RateLimitPolicies.ClientKey` |
| Language selection (PR-B, PR-C1) | The URL alone chooses the language (`/en`, `/en/...` = English, everything else Arabic); the request-culture provider list is replaced by `UrlCultureProvider`, so `Accept-Language`, cookies and query strings are ignored. Aliases get one 301 from `CultureUrlNormalizer` (GET/HEAD only): lower-case, trailing slash, a leading `/ar`, `/Home`, `/Home/Index`, `/en/Index`. The target is a path of the route table plus the original query string, and a path that does not map to a page is left alone (404), so it cannot become an open redirect (`//host`, `/%2fevil.com` and `/ar//evil.com` return 404 with no `Location`). `?page=1` on a list page is a 301 to the bare path; `?page=` out of range, repeated or non-numeric is 404. | `Infrastructure/Localization/Cultures.cs`, `CultureUrlNormalizer.cs`; `Controllers/PublicControllerBase.cs` |
| Site base URL (PR-B) | Canonical, hreflang, `og:url` and `/sitemap.xml` use the admin-set key `site_base_url` (`https://host[:port]` only: no path, query, fragment or user-info). Outside Development it is never taken from the Host header; when unset those tags are omitted and `/sitemap.xml` returns 404. Social-link and footer-credit URLs must be absolute `https://` (`[HttpsUrl]`); nav, platform and news links use `[SafeHref]`; no `href` is written with `Html.Raw`. | `Infrastructure/Seo/SiteUrl.cs`; `Infrastructure/HttpsUrlAttribute.cs`; `Infrastructure/SafeHrefAttribute.cs` |
| Indexing (PR-B, PR-C1) | Per request, fail-closed. A public page records its decision (`SeoPolicy.Decide`: Index, `noindex, follow` or `noindex, nofollow`) in `HttpContext.Items`; the `X-Robots-Tag` header, the page's robots meta, hreflang and `/sitemap.xml` all read that same decision. `noindex, follow` for: a list page with no active item (English: none with English text), a page with neither intro nor body (the home page excepted), an English page without English meta title and description, a page without its `Pages` row. Every other HTML/JSON response without a decision, or whose status is not 200 (login, admin, error, 404, form JSON), gets `noindex, nofollow`; the admin layout and the login page also carry `<meta name="robots" content="noindex, nofollow">`. `robots.txt` disallows `/Admin`, `/admin`, `/forms` and `/en/forms`. The branded 404 does not reflect the requested path. | `Infrastructure/Seo/SeoPolicy.cs`, `RobotsHeader.cs`; `Controllers/SeoController.cs`, `PublicControllerBase.cs` |
| Compression scope | Response compression (Brotli/Gzip) is limited to static css/js/svg/json under `/css`, `/js`, `/assets`, `/lib`. HTML pages (which carry the antiforgery token beside reflected input) and form JSON are never compressed, so a BREACH-style length oracle has nothing to measure. Versioned static URLs (`?v=`) are cached for one year, immutable. | `Infrastructure/StaticAssets.cs`; `Program.cs` |
| Security headers | On every response, static files included: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `Referrer-Policy: strict-origin-when-cross-origin`. No script/style CSP yet (inline script in `Index.cshtml`). Outside Development: HTTPS redirect + HSTS (ASP.NET default, 30 days). | `Infrastructure/SecurityMiddleware.cs`; `Program.cs` |
| Auth cookie | `Innovest.Auth`, HttpOnly, SameSite=Lax, Secure (always, except Development), 8 h sliding. | `Program.cs` |
| Data-protection keys | Persisted to `App_Data/DataProtection-Keys` (content root) so antiforgery tokens and sessions survive restarts; on Windows encrypted with DPAPI, machine scope; elsewhere unencrypted (protect by ACL). Not persisted in the `Testing` environment. `App_Data/` is git-ignored. | `Program.cs` |
| Password-change session invalidation | The principal carries `innovest:pwd` = SHA-256 of the current password hash; on every authenticated request the hash is re-read by user id and the cookie is rejected on mismatch, missing claim or deleted user. Changing the password ends all other sessions; the current session is re-issued. No schema change. | `Infrastructure/AdminSession.cs`; `Program.cs` (`OnValidatePrincipal`); `Controllers/Admin/SettingsController.cs` |
| Admin route scoping (PR-B, PR-C1) | The `admin` route (`Admin/{controller}/{action}/{id?}`) only resolves controllers deriving `AdminControllerBase`; `/Admin/Home/*`, `/Admin/Account/*` and `/Admin/Forum/*` return 404. Since PR-C1 the conventional route `{controller}/{action}/{id?}` is constrained to `Home\|Account` and has no defaults, so an admin controller no longer answers at the site root: `/Dashboard`, `/Events`, `/Faq`, `/Partners`, `/Settings`, `/Pages`... are the 404 page (not the login redirect) and every admin URL starts with `/Admin/`. Anything unmatched falls to the branded 404. | `Infrastructure/AdminControllerConstraint.cs`; `Program.cs` |
| Admin site-structure input (PR-C1) | `Admin/Pages` accepts only a key of the route table (`Edit/..%2fhome`, an unknown key, `ToggleMenu/home` and `Move` with a direction other than ±1 are 404); the posted model has no `Key`, `SortOrder` or `UpdatedAt`, so over-posting them changes nothing; the home page cannot be hidden. `Admin/ContentItems` accepts only the 13 registered groups and icons of a whitelist (`Icons`), the row must belong to the posted group, and `Id`/`IsActive`/`CreatedAt` on Create are ignored. `header_cta_page` must be a route-table key and `list_page_size` a count 1-50 (`ContentRule.PageKey`, `Count`); the contact website must be `https://`. Page texts reach HTML encoded, the JSON-LD graph is serialised by `System.Text.Json` (escapes `< > &`), and `Html.Raw` is used only for whitelisted icon SVG constants and migration-owned `IconSvg`. | `Controllers/Admin/PagesController.cs`, `ContentItemsController.cs`, `ContentController.cs`; `ViewModels/Admin/SiteStructureInputs.cs`; `Infrastructure/Seo/SeoBuilder.cs` |
| Content migrations (PR-C1) | `ApplyCompanyProfile` rewrites placeholder texts only where a value still equals the old seed value, compared **per column** (NULL-safe, binary); a row whose identity columns were edited is left untouched, so an admin edit is never overwritten. The generated up scripts contain 0 `DROP COLUMN`, 0 `DROP TABLE`, 0 `DELETE` (3 `DROP INDEX` of the replaced sort indexes: News, Events, Platforms). Back up first; roll back by restoring the backup, never `Down`. | `Migrations/20261022152940_AddSiteStructure*`, `20261022153329_ApplyCompanyProfile*` |
| Forwarded headers | Off unless `ForwardedHeaders__KnownProxies__0=<ip>` is set (one entry per proxy); never trusts all proxies. Needed only when TLS is terminated in front of the app. | `Program.cs` |
| LocalDB guard | Development/Testing refuse any non-`(localdb)\` connection, at configuration time and on the effective DbContext connection. | `Infrastructure/LocalDbGuard.cs`; `Program.cs` |
| Production-database guard | In **every** environment, a connection that is not `(localdb)\` is refused unless the process is hosted by IIS (any of `APP_POOL_ID` — IIS worker process —, `ASPNETCORE_IIS_PHYSICAL_PATH` or `ASPNETCORE_TOKEN` — ASP.NET Core Module) or `INNOVEST_ALLOW_REMOTE_DB` is exactly `1`. The variable that allowed a remote database is logged at Warning (never the connection string). Checked at configuration time (before `Build()`, so also under `dotnet ef`), again on the effective DbContext connection before `MigrateAsync`/seeding, and on every connection open (`ProductionDbGuardInterceptor`, registered in `AddAppDbContext`: covers `dotnet ef --connection` and every context built through `AddAppDbContext`; a migrations bundle was not tested, and a hand-built `DbContextOptionsBuilder` is not covered); no check connects. LocalDB means a `(localdb)\` data source with no `Failover Partner` and no `MultiSubnetFailover`. Whether IIS Express sets the IIS markers is not verified (no IIS Express launch profile exists). The refusal (`ProductionDbGuardException`) never contains the connection string. Added after a developer-machine run in Production mode migrated the production database (2026-10-22, repaired). | `Infrastructure/ProductionDbGuard.cs`; `Program.cs`; `InnovestHolding.Tests/ProductionDbGuardTests.cs` |

## Known limits (accepted)
- A POST to a form without a valid antiforgery token (400) still spends one of the 5 requests of its rate-limit bucket: the limiter runs before the antiforgery filter (conservative; fails toward blocking).
- The normaliser also accepts `/ar/en/about` and 301s it to `/en/about` (still a route-table path, one hop).
- IPv6 clients are keyed per /64: every host of one /64 shares a budget (PR-B; production has no AAAA record today).
- 5 bad attempts on the admin account lock it for 15 min (recovery: wait, or recycle the app pool).
- Lockout and rate-limit counters reset on restart.
- `IconSvg` columns (nav sub-items, platforms, stats) are rendered as raw HTML; no admin form writes them. Adding an admin field for them needs SVG sanitising first.
